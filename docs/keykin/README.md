# Keykin

Draft · 2026-11-05 · docs only, not built

**The bar:** an nsec kept in a password manager. Every rule must beat it on security *and* ease of use.

Keykin keeps one Nostr key (an ordinary npub) for life without any single device, server or company
holding it. The key is split with FROST (secp256k1, BIP-340 Taproot form) into weighted shares: each of a
person's devices holds 3 points, each of three servers 1, a paper backup 2, and signing takes 4. So the
device in use plus any one server signs, two devices sign together, and the servers alone never can.
Sites and clients see a normal npub and use the NIPs they already use (NIP-07, NIP-46, NIP-55).

## Implementing

1. Read [minimum.md](minimum.md) for the role you are building (site, member device or server), then
   the Core sections it lists.
2. Pass the vectors:
   - `vectors/vectors.json`: computed cases (FROST, indices, hashes, encodings), regenerated by
     `python3 -I vectors/gen_vectors.py`;
   - `vectors/negative.json`: 300 hostile and edge inputs for the JSON profile, encodings, locks, the
     destructive rule, lifetimes, records and membership;
   - `vectors/membersig.json`: member-key signatures for apps;
   - `vectors/vectors.md`: the behaviour cases.
3. Pass the interop tests in [interop-plan.md](interop-plan.md): nak, and standard NIPs.

## Status

Draft. Kind numbers (24301, 24302, 30242, 30243, 10243, 1244–1247, and the vaults spec's 4810–4813, 30810,
30811) are provisional and are pinned before 1.0. Open: an outside review of Core, and a formal check of the
one-call signing round and the one-request list (Core §5.1, §6.7.10).

Known limits are in Core §10 and each module's limits section. [simplification.md](simplification.md) and
[../decisions.md](../decisions.md) record how the design got here. `../COSIGN.md`, `../NIP-XX.md`,
`../servers.md` and `../choosing-servers.md` describe Cosign 0.12, the retired prototype.
