Cosign 0.12.6: three more server fixes from the same week of reviews. **Server operators
should update.** No protocol change, no account change.

**Only a device gets a piece of a decryption.** A server asking its peers for one *is* a
server coordinating a decryption, which §5.6 forbids, and this server answered. On a
weighted key the arithmetic hid it — a server's share and ours are 2 points, short of 4 —
but on a 2-of-3 key the numbers allowed it, and a rule this important shouldn't rest on the
arithmetic. Only a device may ask now. Paired with the browser extension's half of the same
fix (it answered *any* server's request with three points' worth of partials), this closes a
path where one breached server held the secret that opens everything an account encrypts to
itself.

**Nothing enters the archive that the account didn't sign.** The archive checked that an
event's kind was one it keeps and that an id and a signature were *present* — never the
signature itself — and a peer's `sync`, `logged` and `saved` messages were taken on trust.
Everything built on the archive assumes otherwise: a change is judged against the version it
replaces, "dated in the future" is shown to devices and deleted by its id with one tap, and
Undo **signs the content of a saved copy again**. The check now lives in one place inside
the archive, and those three messages are accepted only from a server rather than from
anything that isn't a device.

**A server that was offline keeps what a device deleted.** The server-to-server message for
dropping an archive entry was called `forget`, which is also what a device calls "remove my
servers' pieces", so the clause could never run. It is `archive_forget` now. No compatibility
shim: no version ever honoured the old message.

Also: ordinary NIP-46 clients are now held to it by a test — `site/test/nip46.e2e.ts` drives
a spec-written client and `nak` itself through every method, including the ones Cosign
refuses on purpose.

The server image is ghcr.io/sybenx/cosign-server:0.12.6 (also :0.12 and :latest), for amd64
and arm64. Marble, the Android app, is released from https://github.com/sybenx/marble.
