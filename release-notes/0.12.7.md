# Cosign 0.12.7

Two security fixes found this week, and a decryption round that now proves itself.

## A paper backup is not a device, and may not say it is

`case 'members'` accepted a member list from any member that is not a device, and the paper
backup is one of those. It could send a list in which its own entry said `role: 'device'`, and the
clause that exists for a real case — a paper that became the phone it restored, seen at the other
server — believed it.

That clause is careful about what it grants: unless the server saw the recovery itself it marks
the member `viaServer`, so removing a device, taking the account out and cancelling a wait stay
refused. But `isDevice` ignores that mark, so after the flip the paper holder counted as one of
your devices for everything gated on that alone — **granting an app access above all**, and also
`phone_signed`, `repair_delta`, `refresh_request`, `mail_for`, `revoke` and `undo`. The round that
hands out a piece of a decryption was saved only by the arithmetic of a weighted key, which is not
a reason and is not true of a threshold-2 key.

The point of the paper is that using it is slow and visible: a recovery runs a wait at every
server and every device is told. This path was neither. A member list is now merged only from
another server, which is what the clause always meant.

## A server a generation behind says so, and stops pretending

A server that was away when the key refreshed got neither the plan nor its part from the other
servers, and afterwards refused every later plan, because a refresh plan has to match the share
points it no longer had. Nothing told it, either: the sync the two servers exchange carried
sites, tickets, changes and the archive, and no epoch. So it went on answering rounds with
partials that cannot verify — which reads as a slow server rather than a dead one, while the
group quietly went from three signers to two.

The sync now carries the epoch. A server that finds itself behind says so in words you can read,
shows it on its status page, and refuses to take part in signing and decryption rather than
contributing a piece nobody can use. Mid-refresh is not behind: in the two-phase refresh the
other server commits first and this one keeps signing with its current shares until it commits
too.

It does not repair itself, and it says so: the fix is to take that server out and enroll it
again. A server that comes back within about a minute of the refresh still catches the plan from
the relay and recovers on its own, as it always did.

## A piece of a decryption proves it is the share's

Signing has always verified every partial. A decryption verified none: combining rejected only a
degenerate result, so one wrong piece — a stale share, a corrupted copy at rest, a dishonest
partner — made whoever asked derive a value nobody else has, and the only symptom anywhere was a
message that would not decrypt.

Each piece now carries a Chaum-Pedersen proof that it was made with the share the member list
already publishes, and the asking device checks every one before combining. A piece that does not
match names the server that sent it, and the next server gets a turn. 98 bytes per piece, one
extra scalar multiplication to make and two to check.

Servers answer with the proofs beside the pieces they always sent, so a phone or extension that
does not know about them yet behaves exactly as before. The phone's half is in the Android
library and arrives with the next Marble build.
