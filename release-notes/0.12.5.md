Cosign 0.12.5: three security fixes for servers, found by two independent reviews of a
design proposal and then found to be live in the running code. **Server operators should
update.** Nothing in the protocol changes, and no account changes.

**A server's word no longer makes something one of your devices.** One server of an
account — dishonest, breached, or a friend's box somebody got into — could send the others
a member list containing a "device" whose key it held, and from then on they treated it as
one of the user's devices: it could report every real device lost, which is instant and
final, take the account out, cancel a wait or a paper recovery, and grant apps. It could
never sign (it holds no shares, and partial signatures are checked), so this was permanent
lockout rather than theft of the key. A member learned only from another server's list is
now marked, and those six actions are refused from it until it has proved it holds the
shares the list claims — which it does the first time it signs. Nothing else is gated, so a
device added through one server is never delayed at another.

**A paper backup and a new server wait, and their pieces wait with them.** A paper is 2
points and a server is 1, and either, handed to a key the asking device chose, is the
threshold with that device's own 3: the whole key, from one device, for good. The only gate
was the device saying it had asked for the user's lock. Both now wait an hour
(`COSIGN_ADD_WAIT`), every device is told and woken, any one of them can stop it, and **no
piece is made until the wait ends**. Adding a device is untouched.

**A device reported lost may say it wasn't them.** Reporting is instant and final, the
first report won outright, and the reported device was mute from that moment — so a thief
with one device reported every other device lost and then cancelled each paper recovery the
owner started. A device that has been reported lost now keeps, for a week
(`COSIGN_CONTEST`), the right to report the device that reported it, cancel a wait and
cancel a recovery, and nothing else. Two devices that report each other are both out: a
thief can deny service and can never take over.

Also: every other device is now told in so many words, and woken, when a device is added;
a server takes a paper recovery it watched itself as its own; and a phone no longer makes
repair shares for anything it didn't ask to add (already in Marble 0.12.17).

Two new end-to-end tests run the attacks rather than describing them:
`site/test/hardening.e2e.ts` and `site/test/contest.e2e.ts`.

The server image is ghcr.io/sybenx/cosign-server:0.12.5 (also :0.12 and :latest), for
amd64 and arm64. Running one: docs/servers.md. Marble, the Android app, is released from
https://github.com/sybenx/marble.
